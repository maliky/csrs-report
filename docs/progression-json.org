#+TITLE: Export JSON des taches et progressions
#+LANGUAGE: fr
#+STARTUP: overview

* Routes disponibles

Deux routes repondent a des usages distincts.

- =GET /taches/<id>/progression.json= fournit l'historique d'une seule tache a une session CSRS connectee.
- =GET /observable/progression.json= fournit toutes les taches au seul compte technique =dev=, au moyen d'un jeton temporaire. Cette route est concue pour un chargement direct depuis Observable.

* Chargement global depuis Observable

Apres connexion a CSRS avec le compte technique =dev=, ouvrir =/observable/=, puis utiliser le bouton *Copier le code Observable*. Le lien et cette page ne sont pas disponibles pour les comptes metier. La page genere un jeton signe valable 15 minutes par defaut. Le jeton est envoye dans l'en-tete =Authorization=, jamais dans l'URL et sans transmettre le cookie de session CSRS.

Le code fourni a cette forme :

#+begin_src js
csrs = {
  const response = await fetch("https://csrs.koba.sarl/observable/progression.json", {
    headers: {
      Accept: "application/json",
      Authorization: "Bearer JETON_TEMPORAIRE"
    }
  });
  if (!response.ok) throw new Error(`CSRS ${response.status}`);
  return response.json();
}
#+end_src

Les deux tableaux sont alors disponibles avec :

#+begin_src js
tasks = csrs.tasks
#+end_src

#+begin_src js
progress = csrs.progress
#+end_src

Le serveur reverifie a chaque requete que le detenteur du jeton est encore actif et superutilisateur. La suppression de ce droit ou la desactivation de =dev= invalide donc immediatement un jeton deja emis.

* Schema global

La reponse separe les metadonnees, une ligne par affectation, et les series journalieres, plusieurs lignes par affectation :

#+begin_src json
{
  "schema_version": 1,
  "generated_at": "2026-07-13T14:30:00+00:00",
  "task_count": 1,
  "progress_row_count": 2,
  "tasks": [
    {
      "task_id": 31,
      "task_code": "FIN-2026-0031",
      "task_title": "Rapprocher les pieces de caisse",
      "action_code": "FIN",
      "employee_id": 12,
      "status": "active",
      "start_date": "2026-05-04",
      "due_date": "2026-05-20",
      "planned_work_days": 12.0,
      "completed_on": null
    }
  ],
  "progress": [
    {
      "task_id": 31,
      "start_date": "2026-05-04",
      "day": "2026-05-04",
      "is_working_day": true,
      "due_date": "2026-05-20",
      "planned_work_days": 12.0,
      "elapsed_work_days": 0,
      "remaining_schedule_days": 12.0,
      "overdue_days": 0.0,
      "percentage": 0,
      "observed": false
    },
    {
      "task_id": 31,
      "start_date": "2026-05-04",
      "day": "2026-05-05",
      "is_working_day": true,
      "due_date": "2026-05-20",
      "planned_work_days": 12.0,
      "elapsed_work_days": 1,
      "remaining_schedule_days": 11.0,
      "overdue_days": 0.0,
      "percentage": 15,
      "observed": true
    }
  ]
}
#+end_src

=action_code= vaut =null= lorsqu'une tache n'est pas rattachee a une action institutionnelle. Les champs de charge sont limites au dixieme de jour; une charge entiere reste serialisee comme un nombre JSON, par exemple =12.0=, et une charge fractionnaire comme =12.3=.

=task_id= relie =tasks= et =progress=. =employee_id= permet un regroupement sans exporter le nom du collaborateur. La description, les notes, les observations, les auteurs, les adresses email et les telephones sont exclus.

Chaque date calendaire apparait dans =progress=. Par exemple, la fete nationale du calendrier ivoirien est explicitement non ouvree :

#+begin_src json
{
  "day": "2026-08-07",
  "is_working_day": false
}
#+end_src

Le champ =is_working_day= provient de la version du =WorkCalendar= conservee par la tache. Il vaut =false= pour les samedis, dimanches et exceptions non ouvrees, et =true= pour les jours normalement ou exceptionnellement ouvres.

Une saisie reelle porte =observed: true=. Un jour sans saisie reporte la derniere valeur connue avec =observed: false= ; avant la premiere saisie, la valeur est 0 %. Les compteurs de charge ne progressent que lorsque =is_working_day= vaut =true=. Une tache ouverte s'etend jusqu'a la vraie date du jour. Une tache terminee ou cloturee s'arrete a =completed_at=.

* Securite et CORS

L'API globale accepte seulement un jeton signe de courte duree emis pour le compte technique =dev=. Elle ne depend pas d'un cookie tiers et repond avec un CORS non authentifie par cookie. Le joker =Access-Control-Allow-Origin: *= s'applique uniquement a cette route : le jeton Bearer constitue l'autorisation et =credentials= ne doit pas etre ajoute au =fetch=.

Les reponses portent =Cache-Control: no-store=. Le jeton ne doit etre ni publie, ni committe, ni conserve dans un notebook public. Sa duree se regle avec =OBSERVABLE_EXPORT_TOKEN_MAX_AGE_SECONDS=, qui vaut =900= par defaut.

La route individuelle conserve exactement le schema des lignes de =progress=, mais continue d'utiliser la session CSRS et les permissions de la page de detail.
