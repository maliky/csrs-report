* Processus de gestion des données

** Décisions

- D02 :: l'Application conserve les identifiants, classifications et opérations de gouvernance, mais jamais les datasets eux-mêmes.
- D03 :: Une autorisation d'accès crée un =work item= exécuté et confirmé par TSI ; elle ne provisionne pas directement les droits externes.
- D04 :: La conservation de cinq ans commence à l'archivage et peut être suspendue par un =legal hold= motivé. 
- D05 :: Les décisions, corrections et confirmations doivent utiliser révisions optimistes, =service queues= et événements =append-only= ; les dossiers terminaux restent immutables.
  # revisions optimites?  Qu'est ce ?
- D06 :: Les documents de gouvernance utilisent le stockage privé, le contrôle antivirus, les permissions =server-side= et l'export d'audit du socle.
# > Qu'est ce que le socle ici ?

* Processus de demande et de prolongation de visa

** Décisions constatées

- D01 :: Le visa doit réutiliser le noyau auditable =ProcessCase= avec un =data model= et un =state graph= typés et versionnés, sans mini-BPM administrable.
# > expliquer le ProcessCase et le data /state model utilises  
- D02 :: les validations dans l'application ont valeur de signature.
- D03 :: Les étapes internes passent par des =service queues= avec =claim= et =takeover= audité ; les actions des visiteurs, coursiers et agents MAE sont saisies par un agent interne.
  # expliquer service queues claim takeover, comment sont ils audite.
- D04 :: Les échéances utilisent le calendrier ivoirien en jours ouvrés 
- D05 :: Les pièces sont privées, contrôlées par ClamAV et stockées explicitement en =local private storage= ou via Microsoft Graph ; la lecture hiérarchique reste limitée aux métadonnées. 
- D06 :: Un dossier terminal est immutable et exportable en ZIP d'audit avec originaux, synthèse et =manifest= d'empreintes.

* Processus d'élaboration des ordres de mission

** Décisions

- D03 :: une absence ou une égalité de routage bloque la soumission.
# > donne un exemple condisant a un blocage  
- D04 :: Un agent autorisé effectue un =claim= ; un autre peut faire un =takeover= motivé et audité, sous réserve d'un =RoleGrant= actif.
- D05 :: Django applique toutes les permissions et transitions =server-side= ; la UI n'utilise que les capacités renvoyées par l'API.
- D06 :: Les écritures utilisent une transaction, un verrou et une révision optimiste ; une ancienne révision produit =409 stale_revision= et les événements sont =append-only=.
- D07 :: Pour une mission internationale, le billet peut suivre la demande mais devient obligatoire avant l'envoi au signataire.
- D08 :: Le DG signe avec =SIGNER <reference>=, ou demande une correction motivée, ou rejette ; la signature fige un =snapshot= et le =manifest= SHA-256 des pièces.
- D09 :: Le secrétariat confirme les trois remises obligatoires ; une demande de véhicule crée ensuite un =work item= du parc, sans inventaire ni réservation.
- D10 :: Les pièces PDF, DOCX, JPG et PNG, limitées à 20 Mio, sont contrôlées et analysées avant un stockage privé sans =fallback= silencieux.
- D11 :: L'API versionnée et la UI React couvrent création, inbox, détail, actions, documents, historique et export d'audit sous =/app/processus=.
- D12 :: Les dossiers terminés, rejetés ou abandonnés sont immutables ; la conservation est de trois ans après clôture avec =legal hold= motivé.

* Processus d'élaboration du Bon de sortie de fonds (BSF)

** Décisions

- D02 :: Les visas dans l'application auront valeur de signature.
- D03 :: le DG valide, rejette ou demande une correction motivée sans modifier le contenu.
- D04 :: Les jours de préparation du BSF et de caisse sont fixes
- D05 :: Le contrôle budgétaire et comptable reste manuel dans le périmètre actuel, même si une intégration future est souhaitée.
- D06 :: Le seuil espèces/chèque reste fixé à 200 000 FCFA 
- D08 :: Les versions, motifs, validations et pièces doivent rester auditables ; un dossier terminal est immutable et exportable avec ses preuves.

** Questions ouvertes

- Q01 :: Quel =data model= typé couvre projet, ligne budgétaire, montant, devise, initiateur, bénéficiaire et pièces justificatives ?

- Q03 :: Quel =state graph= exact conserve chaque visa lorsqu'une anomalie ou un rejet DG renvoie le dossier en correction ?
- Q04 :: Quelle preuve structurée accompagne les contrôles manuels de capacité budgétaire et de situation comptable ?
- Q05 :: Quelle matrice de =segregation of duties= interdit les cumuls, et quelles exceptions motivées restent possibles pendant une délégation ?
- Q06 :: Les jours fixes et le délai maximal de trois jours doivent-ils bloquer une transition ou seulement calculer des =due dates= et indicateurs ?
- Q07 :: Quelles données et preuves de paiement conserver pour espèces et chèque sans exposer inutilement des données financières sensibles ?
